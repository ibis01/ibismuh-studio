   131→// S20 — the API token registry. Bearer tokens used to be purely stateless
   132→// (HMAC payload, uid + exp + random jti): nothing listed them, nothing
   133→// revoked them — a leaked token was live for 90 days and the only defense
   134→// was rotating TUBEFORGE_AUTH_SECRET (which kills every session too).
   135→// Sessions got the DB treatment in Stage 2 (jti = Session row id, instant
   136→// revoke); tokens now get the same: every mint persists a row keyed by the
   137→// token's jti, resolveApiCtx refuses revoked/unknown jtis, and the security
   138→// card lists + revokes them. The signed payload is unchanged — only the
   139→// registry gates it now.

   152→  user        User      @relation(fields: [userId], references: [id], onDelete: Cascade)

   556→// S112 — Scene-Level Editing & Repair, Stage 1: the revision foundation

   568→// content snapshots the scene's UNION slice — { scene, docScene }: the row
   569→// Scene AND its timeline-doc TimelineScene — because a scene's editable
   570→// content lives in both documents (rollback of half a scene would be a lie).

  1003→// S32 — the $5 door's durable ledger. S27 kept outstanding reservations in
  1004→// process memory and bootstrapped the recorded total from a SUM of
  1005→// UsageRecord rows. Two gaps the external audit (Nov 2026) called out:
  1006→//   * a crash mid-call lost the hold — the next boot under-counted;
  1007→//   * connection-test dispatches (settings/ai route, outside aiCall) settled
  1008→//     the in-memory recorded total but never wrote a UsageRecord row, so a

  1138→// S46 — durable auth throttling (roadmap P1-6). One row per FAILED
