    25→
    26→These are recorded in the repo (WHITEBOARD_ENGINE_DESIGN.md §1, s87 §0, whiteboard-videoscribe-reconciliation.md §11, ARCHITECTURE.md §1.9) and they bind every stage below:
    27→
    28→| Law | Meaning for this roadmap |
    29→| --- | --- |
    30→| No second renderer | New engines render frames via the proven chromium-screenshot → ffmpeg-encode path; the compositor, QC battery, ship gates and storage seams are shared, unchanged |
    31→| One source of motion truth | Each engine's frame plan is a pure function `frameAt(project, assets, tMs)` shared by editor preview AND final render (the `wb-page.ts` `APPLY_FRAME_FN` pattern) |
    32→| Determinism | Frame N is a pure function of (project, library, N). No CSS animation, no clock, no randomness. Determinism pins = identical frame hashes |
    33→| Compile-to-events / no parallel grammar | New planning layers compile INTO the frozen `AnimationEvent` grammar or project onto S87 `tracks[]`; the grammar itself does not grow |
    34→| Timeline is a projection, never the truth | The video row is truth; tracks are derived/engine-authored projections with a consistency check |
    35→| Native-first ($0 pixels) | Deterministic native rendering is the default; AI video generation (i2v) is the escalation lane, not the base |
    36→| Every unbounded dimension has a named wall | Frame budgets (`WB_RENDER_FRAME_BUDGET = 25_920`), upload budgets, per-scene placement caps — each new engine declares its own walls |
    37→| Leaf-module law | `whiteboard/*` imports only shared infra + siblings; new engines follow the same shape |
    38→| AI suggests, human approves | Director/router output is advisory until an approval checkpoint flips state |
    39→| Every task ships: objective, files, dependencies, acceptance criteria, tests, rollback | The per-stage specs below follow exactly this template |

   176→## 5. Stage spec — G1: the motion-graphics engine
   177→
   178→**Objective:** animated typography, icons, charts, counters, callouts and transitions as a deterministic native engine — the biggest genuine gap (today `slides.ts` animates nothing; it renders static designed PNGs and pushes the camera).
   179→**Pattern:** the whiteboard engine's proven shape, applied to a new grammar — NOT a competing renderer. G1 renders through chromium frame screenshots → ffmpeg, emits S87 tracks of the reserved kind `"graphics"`, rides the shared QC battery.
   180→
   181→**Decision recorded up front (two-phase composition strategy):**
   182→- **Phase 1 — peer lane** (exactly the whiteboard's integration): G1 renders whole graphics-led videos; `render-lane.ts` routes by mode; `render.ts` is untouched. This is the lowest-risk landing and matches the newest proven precedent.
   183→- **Phase 2 — compositor citizenship** (cross-engine videos): a `graphics`-kind segment builder in `render.ts` + schema-3 persisted tracks (Stage X). Phase 2 is gated on Phase 1 shipping and on Stage X's design.
   184→
   185→New files (`src/lib/tubeforge/graphics/`, leaf-module law):
   186→- `graphics/types.ts` — the GraphicsDoc grammar (versioned like `Scene3D`): `GraphicsScene { id, narration, durationMs?, background, elements: GraphicsElement[] }`; `GraphicsElement` variants: `headline`, `subhead`, `bullet`, `counter` (number tween + unit), `bar`/`barChart` (data-driven, not static HTML), `icon` (inline sanitized SVG paths — reuse `svg.ts#sanitizeSvg`/`parsePathData`), `callout`, `shape` (rect/line/circle), `group` (for enter/exit choreography); each element: `{ id, at: Placement, enter: ElementMotion, exit?: ElementMotion, emphasis?: ElementMotion }`; `ElementMotion = { kind: "fade"|"rise"|"slide"|"pop"|"wipe"|"count"|"grow"|"draw", durationMs, delayMs, ease }`; named walls mirroring `WB_BUDGETS` (`elementsPerScene`, `scenesPerProject`, `sceneDurationMsMax`, `GRAPHICS_FRAME_BUDGET`); `validateGraphicsDoc` (tolerant parse, strict write);
   187→- `graphics/anim.ts` — the shared animation substrate (see Stage S below): easing table, keyframe evaluation, clock quantization;
   188→- `graphics/frame.ts` — **the one source of motion truth**: `frameAt(doc, geometry, tMs): GraphicsFrameState` (element transforms/opacities/text states/counters), pure and deterministic; enter/exit/emphasis compose with a fixed precedence (emphasis > exit > enter); bar/count tweens are data-driven pure math;
   189→- `graphics/compose.ts` — HTML/SVG composer (the `composeScene` pattern): static skeleton + one `APPLY_FRAME_FN` applier shared by editor preview and renderer; no CSS animation — every frame applied by JS, deterministic;
   190→- `graphics/render.ts` — the chromium loop (mirror `whiteboard/render.ts`: fresh context per scene, no-network route abort, JPEG quality 92, ffmpeg encode, VO slot normalization `normalizeVoSlot`, music bed under the mix contract); pre-flight frame budget; returns `{ scenes, file, tracks, plan }` with the `plan.totalSec == Σ deliveredSec` assertion;
   191→- `graphics/tracks.ts` — S87 projection: `graphicsTracks(doc, fps, { voSceneIds, musicOn })` → visual track kind `"graphics"` (one clip per scene, `asset: null`), audio + subtitle tracks; the `framePlanClock` pattern re-used so edges are frame-quantized and contiguous by construction;
   192→- `graphics/planner.ts` + `graphics/llm-planner.ts` — native keyword/rule scaffold + LLM spec with per-element degradation to native (the `llm-planner.ts` shape: same schema, planner report, fallback byte-compatible);
